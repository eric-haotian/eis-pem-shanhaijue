## 1. 目的与范围

### 1.1 目的

规定 EASE-PPP 自筛选至归档全生命周期的数据采集、传输、核查、清理、锁定、分析交付、共享与销毁流程，确保数据 **可归因（Attributable）、易读（Legible）、同步（Contemporaneous）、原始（Original）、准确（Accurate）** 且 **完整、一致、持久、可获得**（ALCOA+），并在数据层面**不破坏盲法**。

### 1.2 范围

| 范围内 | 说明 |
|---|---|
| 主试验 EASE-PPP | N=210（盲态样本量再估计后上限 240），三臂 2:2:1，随访至第 52 周 |
| 数据类型 | 电子病例报告表（electronic case report form, eCRF）、电子患者报告结局（electronic patient-reported outcome, ePRO）、中央随机系统（IWRS）分配数据、定量感觉测试（QST）仪器读数、纸质源文件扫描件、影像（去标识化照片） |
| 时间范围 | 首例签署知情同意起 → 第二次数据库锁定（52 周）→ 归档 |
| 范围外（另有文件） | EASE-Sham Pilot（n=30）与 LEAP Registry（N≈300）各自的 DMP；两者与本研究的关联规则见 §16 |

### 1.3 数据管理目标（可度量）

| 指标 | 目标值 | 监测频率 |
|---|---|---|
| 每周 ePRO 完成率（第 −2 至 24 周） | ≥85%；主要终点窗口（第 9–12 周）≥90% | 每周 |
| 主要变量可计算比例（第 9–12 周 4 次中 ≥2 次） | ≥95% | 每月 |
| eCRF 访视后录入及时率（访视后 5 个工作日内） | ≥90% | 每月 |
| 疑问（query）7 天内回复率 | ≥90% | 每月 |
| 锁库时未关闭疑问数 | 0（或经 PI 书面签署的"无法解决"记录） | 锁库前 |
| SAE 24 小时报告达标率 | 100% | 每月 |
| 关键变量源数据核查（SDV）覆盖率 | 100% | 每月 |

## 2. 系统

### 2.1 系统清单

| 系统 | 用途 | 承载方 | 关键要求 |
|---|---|---|---|
| **EDC**（Electronic Data Capture，电子数据采集系统） | eCRF 全部模块、疑问管理、审计轨迹、SDV 标记、数据导出 | 上海中医药大学附属龙华医院**临床研究中心平台**；如平台功能不足，改用**经验证的第三方系统**（须完成 §2.2 验证并签署数据处理协议） | 角色化权限、审计轨迹不可关闭、逻辑核查引擎、电子签名 |
| **ePRO** | 每周与每日疼痛日记、量表、安全筛查题、依从提醒 | 微信小程序 / 短信链接（冻结表 §10） | 患者端不可回溯修改、服务器时间戳、按臂别推送逻辑（后台实现，前台不可见） |
| **IWRS**（Interactive Web Response System，中央网络随机系统） | 随机分配、时间戳、破盲、审计轨迹 | 临床研究中心 IWRS 或经验证第三方（冻结表 §5） | 见 SOP 10；序列导入后不可导出明文 |
| **QST 记录** | PPT（压痛阈）4 部位 ×3 次、TS（时间总和）读数 | 手持压力测痛仪 → 纸质记录单（源数据）→ EDC 录入 | 仪器编号、校准记录、评估者编号必须随读数记录 |
| **统计环境** | 分析数据集生成与分析 | 临床研究中心统计工作站（离线/受控网络） | R ≥4.3 或 SAS；脚本版本控制；`sessionInfo()` 存档 |

**系统间集成原则**：ePRO → EDC 采用**自动接口导入**（首选）或**每周定时批量导入**（次选）；IWRS → EDC 仅传输 `SUBJID`、`RANDDT`、`STRAT_RAND` 与**编码组别（X/Y/Z）**，**不传输 A/B/C**；QST 与纸质源文件由 CRC 人工录入并经二次核对。**任何接口一律单向**（ePRO/IWRS → EDC），EDC 不得回写患者端数据。

### 2.2 计算机化系统验证与稽查轨迹

1. **验证（validation）**：EDC/ePRO/IWRS 上线前完成用户需求说明（URS）、功能规格（FS）、安装确认（IQ）、运行确认（OQ）、性能确认（PQ）与用户验收测试（UAT）；测试用例覆盖：权限越权、逻辑核查触发、审计轨迹完整性、ePRO 时间戳与迟录窗口、并发随机、断网恢复、数据导出一致性、备份恢复。验证文档存 TMF。
2. **审计轨迹（audit trail）**：全系统启用且**不可关闭**；记录操作人（实名唯一账号）、时间戳（UTC+8，服务器时间）、操作类型（新增/修改/删除/查看）、变更前后值、变更原因；**只增不改**，系统管理员亦不可删除；**查询式访问（read access）同样记录**。
3. **变更控制**：系统配置、eCRF 结构、逻辑核查规则、ePRO 问卷任何变更须经变更申请单 → 数据管理员评估影响 → PI 与统计师批准 → 测试环境验证 → 生产环境发布 → 版本号与生效日期记录 → 已录数据的影响评估与必要的回溯处理。**首例入组后的 eCRF 结构变更须同时评估是否需报伦理委员会**。
4. **电子签名**：研究者对 eCRF 的确认、AE 因果关系判定、疑问回复采用系统内电子签名（账号 + 口令二要素），签名记录与被签名数据版本绑定。
5. **时间同步**：全部服务器与 NTP 源同步，时区固定 UTC+8。

### 2.3 个人信息保护与合规

1. **法律依据**：《中华人民共和国个人信息保护法》（PIPL）【待核实条款号】、《中华人民共和国数据安全法》【待核实条款号】、《涉及人的生命科学和医学研究伦理审查办法》（国卫科教发〔2023〕4号）【待核实条款号】、《医疗卫生机构开展研究者发起的临床研究管理办法》（国卫科教发〔2024〕32号，第二十一条 PI 全程管理职责 **[VERIFIED-S]**、第二十五条 启动前 30 日完成登记 **[VERIFIED-S；原文表述待核实]**）。
2. **敏感个人信息**：本研究处理医疗健康信息与生育相关信息，属敏感个人信息，须取得**单独同意**【待核实条款号】——落实为 ICF 中的独立勾选条款（数据处理、数据共享、LEAP 关联、生物样本如有）。
3. **最小必要**：仅采集方案与法规所需变量；**不采集身份证号**；姓名、手机号、住址仅存于**受试者鉴认代码表**（纸质 + 加密电子表），不进入 EDC 分析库。
4. **去标识化**：EDC/ePRO 内一律使用 **受试者号 EASE-XXX**（冻结表 §10）；导出数据集中不含任何直接标识符；照片与影像上传前遮蔽面部与可识别特征，文件名仅含编号与日期。
5. **境内存储**：全部数据存储于**中国大陆境内**服务器；**不向境外提供**；如未来国际合作需数据出境，须另行完成法定评估与伦理批准【待核实条款号】。
6. **个人权利**：受试者可查阅、更正其个人信息，可撤回同意；**撤回同意后停止继续收集，但撤回前已收集的数据仍用于分析**（须在 ICF 明示）。
7. **安全事件**：发生数据泄露或疑似泄露，数据管理员 **24 小时内**报 PI 与临床研究中心，按院内规定与法定要求上报并通知受影响个人【待核实条款号】。

## 3. 角色与权限矩阵

**账号原则**：实名唯一账号，禁止共享；权限按**最小必要**授予；角色变更/离职当日停权；权限授予与变更由数据管理员执行并记录于《系统权限授予与变更日志》（附录 C1）。

| 角色 | 可**查看** | 可**新增/修改** | **不可见** | 盲态 |
|---|---|---|---|---|
| **PI（田立霞）** | 全部 eCRF（编码组别 X/Y/Z 形式）、疑问、AE/SAE、方案偏离、进度报表 | AE 因果关系终裁、SAE 报告签署、方案偏离审批、破盲发起 | 随机序列、区组信息、种子、未破盲个案的 A/B/C | 盲（除已破盲个案） |
| **研究协调员 CRC** | 本研究全部受试者的 eCRF、访视计划、疑问、ePRO 完成状态 | 全部 eCRF 录入与修改（含筛选、访视、合并用药、治疗记录）、疑问回复、电话补录 | 随机序列、A/B 之分（IWRS 只显示"针刺组/常规治疗组"） | 部分盲（不知 A/B） |
| **针灸医师** | 本人当日治疗的受试者的治疗记录模块、AE 模块 | 治疗记录（穴位、mA、留针、针数清点）、AE 初判（针刺/器械因果关系） | 其他受试者数据、随机序列、结局数据（NRS、问卷、QST） | 不设盲（知本人受试者 A/B） |
| **针灸排班员** | 排班信息 + 分配（A/B） | 排班表 | eCRF 全部结局数据 | 不设盲 |
| **盲态评估者** | 本人负责的 QST 与 12/24 周问卷录入界面 | QST 读数、问卷录入 | AE 模块、治疗记录模块、合并用药中的针刺相关内容、随机与组别、其他受试者数据 | **严格盲** |
| **数据管理员** | 全部 eCRF、审计轨迹、疑问、逻辑核查结果、编码组别 X/Y/Z、**LEAP 编号映射表** | 逻辑核查规则、编码（AE/合并用药）、疑问发起、数据集导出、锁库执行 | **A/B/C 真实组别**、随机序列、种子 | 盲（冻结表 §5） |
| **盲态统计师（主分析）** | 锁定后的分析数据集（组别为 X/Y/Z） | 分析脚本 | A/B/C 映射表（主分析前） | 盲（冻结表 §5） |
| **独立统计师** | 随机序列、X/Y/Z↔A/B/C 映射表、盲态 SSR 数据集 | 随机序列生成、SSR 计算、映射表保管 | — | 非盲（不参与主分析） |
| **独立安全监查员 ISM** | 按 X/Y/Z 编码的 AE/SAE 汇总与个案叙述、入组与暴露汇总 | 审查意见书 | 结局数据（疗效）、随机序列 | 盲（可申请个案破盲） |
| **IWRS 管理员** | IWRS 运行日志、账号管理、序列导入状态 | 账号、序列导入执行、故障处置、信封记录补录 | 不主动查阅个体 arm；eCRF 结局数据 | 操作性非盲（受限） |
| **监查/质控员（临床研究中心）** | 全部 eCRF（X/Y/Z）、源文件、SDV 记录 | SDV 标记、发现问题记录 | 随机序列、A/B/C | 盲 |
| **受试者** | 本人 ePRO 已提交内容（只读） | 本人 ePRO 在提交前可修改；**提交后不可修改** | 全部他人数据、组别 | 盲（A/B），C 臂非盲 |

> **交叉限制（强制）**：① 盲态评估者账号**不得**获得 AE 模块与治疗记录模块的任何读权限；② 针灸医师账号**不得**获得结局数据读权限；③ 数据管理员与盲态统计师账号在 IWRS 中**不存在**；④ 任何一人不得同时持有"盲态评估者"与"CRC"两个角色；⑤ 独立统计师不得持有 EDC 的数据修改权限。

## 5. 数据标准

### 5.1 变量命名（沿用 CRF 模块编号，全部大写，下划线分隔）

| 规则 | 示例 |
|---|---|
| 受试者标识 | `SUBJID` = `EASE-001` … `EASE-240`（格式 `EASE-\d{3}`，全局唯一） |
| 每周 ePRO 变量：`指标_Wnn`（`nn` = 研究周，`M02` 表示第 −2 周） | `NRS_AVG_W09`（第 9 周"过去 7 天平均盆腔痛"）、`NRS_WORST_W09`、`NRS_BOTHER_W09`、`NRS_NONMENS_W09`、`ANALG_DAYS_W09` |
| 按月 ePRO | `NRS_DYSMEN_Mnn`（痛经，有月经者）、`NRS_DYSPAR_Mnn`（深部性交痛，有性生活者） |
| 派生主要/关键次要变量 | `PRIM_M0912`（第 9–12 周 4 次均值）、`KEY_M2124`（第 21–24 周均值）、`BASE_MEAN`（筛选期 2 周均值） |
| 访视量表：`工具_域_访视` | `CSI_TOT_V1`、`PCS_TOT_V2`、`PHQ9_TOT_V3`、`PHQ9_Q9_V1`、`GAD7_TOT_V1`、`ISI3_TOT_V1`、`EHP30_PAIN_V2`、`EHP30_TOT_V2`、`BPI_INT_V2`、`PGII_V2` |
| QST | `PPT_LABD_1..3`、`PPT_RABD_1..3`、`PPT_LTA_1..3`、`PPT_RTA_1..3`（kPa 或 N/cm²，单位固定并在字典声明）、`PPT_*_MEAN`（派生）、`TS_FIRST`、`TS_LAST`、`TS_DELTA` |
| 治疗记录 | `TRT_DT_nn`、`TRT_MA_nn`（mA，1 位小数）、`TRT_RET_nn`（留针分钟）、`TRT_POINTS_nn`、`TRT_ADJ_nn`（加减穴，≤2）、`TRT_NEEDLE_IN_nn` / `TRT_NEEDLE_OUT_nn`（针数清点） |
| 安全性 | `AE_SEQ`、`AE_TERM_VERB`（逐字）、`AE_TERM_CODE`、`AE_STDT`、`AE_ENDT`、`AE_SEV`（1–3）、`AE_SER`（Y/N）、`AE_REL_NEEDLE` / `AE_REL_DEV` / `AE_REL_BKG`（1–5）、`AE_EXPECT`、`AE_OUT` |
| 随机与分层 | `RANDDT`、`RANDTM`、`ARM_CODE`（X/Y/Z）、`STRAT_RAND`、`STRAT_TRUE`、`SLOT_NO`、`RAND_METHOD`（IWRS/ENVELOPE） |
| 状态与派生标志 | `ITTFL`、`PPFL`、`COMPFL`（依从：≥16 次且末次治疗 ≤ 随机+98 天）、`PREG_FLAG`、`RESURG_FLAG`、`EXTACU_FLAG`（研究外针灸）、`NEWHORM_FLAG` |

**禁止**：变量名中出现 `A`/`B`/`C` 组别字样；禁止建立任何"组别可推断"的派生变量（如 `SHAM_FLAG`）。

### 5.2 日期、时间与单位

- 日期一律 **ISO 8601 `YYYY-MM-DD`**；时间 `HH:MM`（24 小时制，UTC+8）；
- **部分未知日期**：年月已知日不详记为 `YYYY-MM-UN`；仅年份已知记为 `YYYY-UN-UN`；分析时的填补规则（如取月中）由 SAP 规定，**数据库中不填补**；
- 单位固定：压痛阈 **kPa**（若仪器输出 N/cm²，在字典中声明换算并统一）、电流 **mA**（1 位小数）、时间 **min**、身高 **cm**、体重 **kg**、囊肿最大径 **cm**、体温 **℃**；
- NRS 为 **0–10 整数**；量表总分按各量表原始计分规则，**不做任何标准化后入库**（标准化在分析阶段完成）。

## 6. 数据录入与 ePRO 导入规则

### 6.1 eCRF 录入

1. **及时性**：访视/治疗后 **5 个工作日内**完成录入；SAE 相关模块见 SOP 12 §6（24 小时报 PI，模块 16 同步）。
2. **源数据优先**：录入依据纸质源文件或门诊/住院电子病历；**eCRF 本身作为源数据的字段必须在《源数据确认表》中事先声明**（如治疗当次的针数清点、AE 逐字描述）。
3. **二次核对**：QST 读数、随机相关字段、主要终点相关字段由第二人（CRC 或质控员）100% 复核并在系统中标记。
4. **修改**：任何修改经审计轨迹记录并填写修改原因（下拉选项 + 必要文本）；**不得覆盖原值**；纸质源文件修改采用单横线划改 + 签名 + 日期，禁止涂改液。
5. **缺失填写**：确实无法获得的数据填 `ND`（未做）或 `UNK`（不详）并说明，**禁止留空**、**禁止填 0 代替缺失**。

### 6.2 ePRO 规则（患者端）

| 规则 | 内容 |
|---|---|
| 推送 | 每周日推送每周问卷（冻结表 §10）；每日日记在第 −2–0、11–12、23–24 周每日推送；第 25–52 周每月推送 |
| **时间戳** | 以**服务器接收提交的时间**（UTC+8）为准，记为 `EPRO_SUBMIT_DTM`；同时记录 `EPRO_WEEK`（目标研究周）与 `EPRO_OPEN_DTM`（打开问卷时间） |
| **有效填报窗口** | 每周问卷窗口 = 目标周的周日 00:00 至次周日 23:59（7 天） |
| **72 小时迟录窗口** | 窗口结束后 **72 小时内**仍可补填，系统自动置 `EPRO_LATE=1`；**超过 72 小时患者端自动关闭该周问卷** |
| 超窗补救 | 超过 72 小时者由 CRC 电话采集，录入 EDC 对应模块，置 `EPRO_SRC=PHONE`、记录采集日期与采集人；**电话补录数据在主分析中与 ePRO 数据同等使用，但须在敏感性分析中单独标记**（SAP 规定） |
| **患者不可回溯修改** | 提交后患者端即锁定，**任何情况下患者不得修改已提交内容**；如患者主动报告填错，由 CRC 发起疑问，经 PI 批准后由数据管理员在 EDC 侧作**修正记录**（原值保留、新增修正值与原因，审计轨迹完整） |
| 未填提醒 | 未填者在 48 小时后由系统再次提醒 + **CRC 电话补救**（冻结表 §10）；连续 2 周未填触发 CRC 面访/微信联系；连续 3 次不同日期联系失败方可判定失访（`WD06`） |
| 防重复 | 同一 `SUBJID` + `EPRO_WEEK` 唯一；重复提交仅保留首次，第二次记为异常并触发疑问 |
| 完整性 | 每周问卷内单个 NRS 条目**必答**方可提交；量表条目缺失规则见 §10.2 |
| 设备与账号 | 每个 `SUBJID` 绑定一个微信/手机号；更换手机号须 CRC 在 EDC 中登记变更并留痕；**禁止代填**（家属协助须记录 `EPRO_ASSIST=1`） |
| 不推送内容 | ePRO 界面**不显示**任何组别信息；A/B 臂追加的针刺部位安全题由后台按臂推送，**推送规则对 CRC 与数据管理员不可见**（SOP 11） |

### 6.3 IWRS → EDC 导入

- 每日自动同步（或随机后即时同步）：`SUBJID`、`RANDDT`、`RANDTM`、`STRAT_RAND`、`SLOT_NO`、`RAND_METHOD`、`ARM_CODE`(X/Y/Z)；
- 数据管理员每月执行 **IWRS–EDC 随机记录对账**（100%，见 §9），任何不一致列为重大问题并立即上报（SOP 10 §5.4）。

## 8. 疑问（query）管理

| 环节 | 规则 |
|---|---|
| 发起 | 系统自动（逻辑核查触发）或数据管理员/监查员手动；每条疑问含：编号、`SUBJID`、模块与字段、疑问类型（缺失/超范围/不一致/超时/待核实）、疑问文本（**中性措辞，不得提示期望答案，不得暴露组别**）、发起人、发起日期、优先级 |
| **回复时限** | 责任人（通常 CRC，医学判断类为研究者）须在 **7 个自然日内**回复 |
| 回复要求 | 必须给出**处置结论**：已更正（附更正值与依据）/ 确认原值正确（附说明）/ 数据确实无法获得（填 `ND`/`UNK` 并说明原因）；仅回复"已知悉"不予关闭 |
| 关闭 | 由发起人（数据管理员）审核后关闭；不接受则重新发起（`-R1`、`-R2` 后缀） |
| **升级机制** | 第 8 天系统自动提醒 CRC 与 PI；第 **15 天**升级至 PI（PI 须书面回应）；第 **22 天**升级至临床研究中心质量负责人并列入月度质量报告；第 **30 天**由 PI 与临床研究中心共同决定处置（含现场核查） |
| 优先级 | **紧急**（安全性、资格、随机、主要终点）：3 个工作日内回复；**常规**：7 天；**低**（描述性字段）：14 天 |
| 锁库前 | 全部疑问必须关闭；无法解决者转为《未解决问题清单》，由 PI 与统计师逐条签署处置意见（通常按缺失处理），纳入锁库核查清单（附录 C4） |
| 记录 | 疑问全生命周期留痕于 EDC，导出后随 TMF 归档 |

## 9. 源数据核查（Source Data Verification, SDV）

**执行人**：临床研究中心监查/质控员（盲态）；**频率**：**每月**一次现场核查（冻结表 §10 质控要求）。

### 9.1 100% 核查的关键项

| 项目 | 核查内容 |
|---|---|
| **知情同意** | ICF 版本号与伦理批件一致；受试者与研究者签名及日期齐全；签署日期 ≤ 任何研究相关操作日期；受试者获得副本的记录；如有再同意（新版本 ICF），核查再同意记录 |
| **资格（纳排）** | 逐条核对源文件：手术记录/出院小结/病理报告复印件、超声报告、尿 hCG、合并用药源证据（处方/门诊病历）、筛选期 2 周 NRS 的 ePRO 原始提交记录 |
| **主要终点** | 第 **9–12 周**与第 **21–24 周**每周 NRS 的 ePRO 提交记录（时间戳、`EPRO_LATE`、`EPRO_SRC`）与 EDC 导入值 **逐条比对**；电话补录者核对电话记录单 |
| **SAE** | 模块 16 与住院病历/出院小结/检验影像报告逐项比对；报告时限（24 小时）核实 |
| **随机分配** | IWRS 记录（`SUBJID`、`RANDDT`、`RANDTM`、`STRAT_RAND`、`SLOT_NO`、`ARM_CODE`）与 EDC 100% 一致；信封启用者核对附录 A2/A3 记录与次日 IWRS 补录一致性 |

### 9.2 10% 随机抽查

- 抽样对象：上述之外的全部模块（人口学、病史、QST、量表、治疗记录、合并用药、一般 AE）；
- 抽样方法：数据管理员用**固定种子的 R 脚本**每月生成抽样清单（按已入组受试者随机抽取 10%，每受试者随机抽取 3 个模块），清单与脚本存档，**保证可重现**；
- 若某模块抽查错误率 >5%（错误字段数/核查字段数），则该模块**扩大至 100% 核查**并启动 CAPA。

### 9.3 SDV 记录与产出

- EDC 内逐字段 SDV 标记（已核/未核/有差异）；
- 《月度监查报告》：核查例数、字段数、差异数与类型、已发起疑问数、CAPA 状态；报 PI 与临床研究中心；
- **核查人不得接触随机序列与 A/B/C 组别**；发现可能导致去盲的记录（如源文件中写有"假针"字样）立即报 PI 并按 SOP 11 处理。

## 10. 缺失数据的预防与处理

### 10.1 预防（数据管理侧）

1. ePRO 周日推送 + **48 小时未填自动提醒 + CRC 电话补救**（冻结表 §10）；
2. **72 小时迟录窗口**（§6.2）保留合法补填路径；
3. 每周生成《ePRO 完成率看板》（按受试者、按周、按编码组别汇总仅供数据管理员），连续 2 周未填触发面访；
4. 主要终点窗口（第 9–12 周、第 21–24 周）**前 1 周**由 CRC 主动电话/微信提醒；
5. 访视前 3 天与前 1 天两次提醒；V2/V3 因故超窗者优先安排补访（仍记录实际日期与超窗天数）；
6. 交通补贴按访视发放，降低经济性失访（冻结表 §12）；C 臂 24 周后免费延迟治疗提高保留率（冻结表 §3.3）；
7. **退出后仍继续收集**：`WD_TRT` 与 `WD_FU` 者继续 ePRO 或电话随访（SOP 12 §8）；
8. 每例缺失访视/缺失周均填写**《缺失原因追踪表》**（原因码：忘记/太忙/身体不适/手机问题/不愿填/失联/其他），供 SAP 的缺失机制（MAR/MNAR）论证使用。

### 10.2 数据库内的处理原则

- **数据库中不进行任何填补**（imputation）；缺失即为缺失，以空值 + 原因码表示；
- **量表条目缺失的合分规则**（在数据字典中固定，与 SAP 一致）：CSI（25 条）缺失 ≤2 条时按已答条目均值补齐后取整，≥3 条则总分缺失；EHP-30、PCS、BPI-SF 按各量表原始手册规则处理【量表手册规则待核实并在 V1.1 固定】；PHQ-9、GAD-7 任一条目缺失则总分缺失（因涉及临床判断，尤其第 9 项）；
- **主要变量派生规则**：`PRIM_M0912` 需第 9–12 周 4 次中 **≥2 次**非缺失（EC-20）；`KEY_M2124` 同理（EC-21）；
- **多重填补（multiple imputation, MI）在分析阶段由统计师执行**（MAR，辅助变量：各周 NRS、PGI-I、依从次数，冻结表 §7），DMP 仅负责提供完整的辅助变量与缺失原因码；
- **伴发事件后的数据**：妊娠、再次盆腔手术后的数据按 hypothetical 策略在**分析阶段**处理为缺失（冻结表 §1）；**数据库仍如实记录这些数据**，并以 `PREG_DATE`、`RESURG_DATE` 派生标志供分析切分。

## 11. 盲态数据审查与盲态 SSR 数据集

### 11.1 盲态样本量再估计（SSR）数据集

- **触发**：入组达 **100 例**（冻结表 §6）；
- **数据集内容**：`SUBJID`（可替换为随机序号）、`BASE_MEAN`、`PRIM_M0912`（已可计算者）、`STRAT_RAND`、年龄、时间自手术、疼痛亚型、既往针灸经验；
- **绝对不含**：`ARM_CODE`（X/Y/Z）、任何治疗次数/治疗记录变量、任何可推断组别的字段（如 mA、针感、盲法问卷、C 臂特有的接触记录标志）；
- **产出**：由**独立统计师**计算**盲态合并标准差（pooled SD）**（三臂混合，不拆分）；若合并 SD >2.4 按预设规则上调样本量，**上限 240，不做效应量调整**；
- **输出物**：一页报告，仅含"合并 SD 值 + 建议 N + 是否触发上调"，报指导委员会与伦理委员会备案；**不得输出任何分组统计量、不得输出组间差异**；
- **数据管理员在导出前执行"泄露检查"**：逐列确认无组别相关字段，并由第二人复核签字（附录 C4 同款核查表）。

### 11.2 锁库前盲态数据审查会（Blinded Data Review Meeting, BDRM）

- **参加人**：PI、统计师（盲态）、数据管理员、CRC、临床研究中心质控员；**独立统计师不参加**；
- **时点**：全部疑问关闭后、主数据库锁定前；
- **审议内容（全部在 X/Y/Z 编码或不分组状态下进行）**：
  1. 方案偏离逐例分级（轻微/重大）与 **PP 人群**判定（依从 ≥16 次且无重大偏离，冻结表 §7）；
  2. **ITT 人群**确认（全部随机者）；
  3. 缺失数据模式与缺失原因码汇总，MI 辅助变量可用性确认；
  4. 离群值逐例裁定（保留/核实后更正/标记为敏感性分析对象）；
  5. AE 编码一致性复核与 AE–SAE 对账结果；
  6. 伴发事件标志（`PREG_FLAG`、`RESURG_FLAG`、`EXTACU_FLAG`、`NEWHORM_FLAG`）逐例确认；
  7. 分析数据集规格（ADSL/ADPAIN/ADQOL/ADQST/ADAE/ADCM）与 SAP 的对应确认；
- **产出**：会议纪要 + 决议清单，**全体参加人签字**；纪要签字后 SAP 不得再修改（SAP 定稿以此为界）；纪要存 TMF。

## 12. 数据库锁定与解锁

### 12.1 两次锁定

| 锁定 | 范围 | 时点 |
|---|---|---|
| **主锁定（Primary lock）** | 第 −2 周至第 24 周（V3）全部数据，含主要终点、全部关键次要终点、安全性 | **末例 V3 完成后 8 周内**（冻结表 §10、§11 里程碑 40–43 月） |
| **远期锁定（Long-term lock）** | 第 25–52 周 ePRO 与 V4 数据（探索性） | 末例 V4（第 52 周 ±30 天）完成后 8 周内 |

> **说明（对冻结表的实施细化）**：冻结表 §10 规定"数据锁定：末例 24 周访视后 8 周内"，而 §4 与 §8 同时要求收集 52 周数据。本 DMP 据此设两次锁定：主锁定严格执行"末例 V3 后 8 周内"并支撑主分析与投稿；52 周数据在其后单独锁定与分析，**不影响主分析的时间与盲态**。此细化须经 PI 与统计师确认。

### 12.2 锁定标准（附录 C4 逐条核对，全部满足方可锁定）

1. 末例 V3（或 V4）已完成或已判定失访；
2. 全部 eCRF 页面状态 = 完成且经研究者电子签名；
3. 全部逻辑核查（EC-01…EC-38）无未处理触发；
4. 全部疑问关闭，或已列入《未解决问题清单》并经 PI 签署；
5. SDV 完成：关键项 100%、抽查 10%（含扩大核查的模块）；
6. AE 编码完成并经 PI 复核；AE–SAE 对账一致；SAE 全部有转归或稳定记录；
7. 方案偏离全部记录并分级；ITT/PP 人群清单冻结；
8. IWRS–EDC 随机记录 100% 对账一致；信封启用例次全部完成次日核对；
9. ePRO 与 EDC 导入记录数一致（逐周对账）；
10. BDRM 纪要签字；
11. 数据字典、编码表、逻辑核查规格表、分析数据集规格全部定稿并版本归档；
12. 备份与恢复测试在近 30 天内成功执行一次。

### 12.3 锁定操作

- 由**数据管理员**执行，PI 与统计师**书面授权**；
- 系统层面将全部数据置为**只读**；生成锁定快照（含 SHA-256 校验值）与《数据库锁定声明》，由 PI、统计师、数据管理员三方签字；
- 锁定后**独立统计师**向盲态统计师移交 **X/Y/Z ↔ A/B/C 映射表**（SOP 10 §9、SOP 11）；
- 分析数据集自锁定快照生成，生成脚本与 `sessionInfo()` 存档。

### 12.4 解锁（unlock）流程

- **仅在**发现影响分析结论的重大错误时启动；
- 流程：书面《解锁申请》（申请人、字段、错误证据、影响评估）→ 数据管理员评估 → **PI 与统计师共同批准**（若已揭盲，须同时说明揭盲状态并评估偏倚风险，必要时报伦理委员会）→ 解锁 → **仅修改申请中列明的字段**（全程审计轨迹）→ 第二人复核 → 重新锁定并生成新快照与新版本号 → 《解锁记录》存 TMF；
- 已揭盲后的解锁须在最终研究报告与发表文章中**披露**。

## 13. 备份与安全

| 项目 | 要求 |
|---|---|
| **备份频率** | **每日**增量备份（凌晨自动执行）；**每周**全量备份；**每月**一份异地/异机副本 |
| 备份介质与保留 | 加密存储；日备份保留 30 天、周备份保留 12 个月、月备份保留至归档期满 |
| **恢复演练** | **每季度**一次恢复测试（在测试环境还原并校验记录数与校验值），出具报告存 TMF；锁库前 30 天内必须成功执行一次（§12.2 第 12 条） |

| **静态加密** | 数据库与备份文件 AES-256 加密；密钥由临床研究中心信息岗与数据管理员分持（双人控制） |
| **服务器位置** | **中国大陆境内**（§2.3 第 5 条）；机房具备门禁与环境监控 |
| **账号与认证** | 实名唯一账号，禁止共享；口令长度 ≥12 且含三类字符，**90 天更换**，禁止重复近 5 次口令；**数据管理员、IWRS 管理员、系统管理员强制双因素认证（MFA）**；连续 5 次失败锁定 30 分钟 |
| **访问日志** | 登录、登出、查询、导出、权限变更全部记录；日志**保留至归档期满**，每月由数据管理员抽查异常访问（非工作时间访问、批量导出、越权尝试）并记录复核结论 |
| **导出控制** | 数据导出仅数据管理员与统计师可执行，每次导出记录导出人、时间、范围、去向、用途；导出文件加密并加水印/编号 |
| **终端** | 研究用终端设置屏幕锁（≤10 分钟）、全盘加密、禁用未授权 U 盘；纸质源文件与鉴认代码表存上锁柜 |
| **鉴认代码表** | **受试者鉴认代码表**（姓名/手机号/`SUBJID` 对应）：纸质版存妇科上锁柜，电子版单独加密文件，仅 PI 与 CRC 可访问；**不进入 EDC，不进入任何分析数据集** |
| **销毁** | 保存期满后按医院规定销毁，电子数据不可恢复擦除，纸质碎纸，出具销毁记录【待核实：医院销毁规定】 |

## 16. 与 LEAP Registry 的数据关联

1. **对象**：LEAP Registry（Longhua Endometriosis surgery pain phenotype Registry，前瞻性手术疼痛表型队列，N≈300，冻结表 §14）中被邀请并入组 EASE-PPP 的受试者。
2. **关联方式**：**编号映射表**（`LEAP_ID` ↔ `SUBJID`）**仅由数据管理员保管**（冻结表 §14），加密单独存放，**不进入任何一方的数据库、不进入分析数据集、不随数据共享提供**。
3. **访问控制**：映射表的每次使用须有书面申请（申请人、目的、变量清单、伦理依据），经 PI 批准并记录；使用后生成的关联数据集仅含**去标识化的研究编号**（另行生成 `LINK_ID`），映射关系不随数据集流转。
4. **伦理依据**：LEAP Registry 与 EASE-PPP 分别有独立方案与伦理批件；LEAP 同意书含"同意被邀请参加 EASE-PPP"（冻结表 §14）；**关联分析须在两个方案的伦理批准范围内**，超出范围者另行申请。
5. **可关联变量（示例）**：术前 NRS 组套、CSI、PCS、EHP-30、期待、PPT（可选）；术中 rASRM 分期、Enzian 分类、病灶类型、切除完整性；术后药物方案；LEAP 的 3/6/12 个月随访结局。
6. **分析定位**：关联分析为**探索性**（对应冻结表 §1 的 E-6/E-7 表型问题），须在 SAP 或独立分析计划中预设，**不得用于主分析**，且不得因关联而破坏 EASE-PPP 的盲态（关联数据集在主锁定前不得包含组别信息）。
7. **审计**：映射表的创建、每次访问与销毁均记录于《LEAP 关联使用日志》，随 TMF 归档。
